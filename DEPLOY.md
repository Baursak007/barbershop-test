# Запуск сайта стоматологии: что нужно сделать

Сайт технически готов, но **не готов к показу пациентам**, пока в нём заглушки. Пройди список сверху вниз.

## 0. Что получить от клиники (без этого публиковать нельзя)
- Полное название организации, БИН, номер и дату лицензии на медицинскую деятельность.
- Адрес, как найти вход, телефон, WhatsApp, Instagram, режим работы.
- Список врачей: имя, специальность, стаж, разрешение на публикацию. Фото только с их согласия.
- Актуальный прайс. Цены «от» должны совпадать с тем, что клиника реально берёт.
- Подтверждение каждого пункта из блока «Безопасность и стерильность» и срока гарантии.
- Способы оплаты и условия рассрочки, если она есть.
- Настоящие отзывы (с разрешения авторов) или ссылка на карточку в 2ГИС/Google.

## 1. Замени данные (`js/data.js`)
1. Пройди файл сверху вниз и замени все заглушки.
2. `demo: true` поменяй на `demo: false`. Тогда уйдёт жёлтая плашка и включится микроразметка для поисковиков.
3. `siteUrl` — адрес сайта после публикации.
4. Врачей, отзывы и рассрочку, которых нет у клиники, оставь пустыми (`[]` или `""`): блоки скроются сами.
5. В `index.html` проверь `<title>` и описание в начале файла: они показываются, пока не загрузился JavaScript, и должны совпадать с `seoTitle` и `seoDescription`.
6. В `robots.txt` и `sitemap.xml` замени `example.com` на реальный адрес.

## 2. Юридическая часть
- Отдай `privacy.html` юристу клиники. Это шаблон, а не готовый документ. После проверки удали жёлтое предупреждение (оно исчезнет само при `demo: false`).
- Проверь с юристом требования к рекламе медицинских услуг в Казахстане: какие формулировки, фото и обещания допустимы, что нужно указывать (лицензия и фраза о противопоказаниях уже выведены в подвале).
- Если подключаешь Метрику, упомяни cookie и статистику в политике (в шаблоне это уже есть).
- Не публикуй фото «до и после» и фото пациентов без письменного согласия.

## 3. Приём заявок: выбери один вариант
| Вариант | Как | Минусы |
|---|---|---|
| **A. Мессенджер (сейчас)** | В `CONFIG` укажи `whatsapp` или `telegram` | Заявка дойдёт, только если человек нажал «Отправить» в чате |
| **B. Свой сервер или бот** | Укажи адрес в `formEndpoint`: сайт отправляет JSON, твой сервер присылает заявку администратору в Telegram | Нужен небольшой сервер (VPS). Это отдельный платный продукт для клиента |

Правила для варианта B:
- Токен Telegram-бота хранится только на сервере, в `.env`. В сайт его **никогда** не кладут.
- Сервер должен принимать запросы с адреса сайта (CORS), проверять поля и ограничивать частоту запросов.
- Формат данных: `type`, `name`, `phone`, `concern`, `doctor`, `date`, `time`, `visitType`, `plan`, `planTotal`, `consent`, `page`, `createdAt`.

Перед запуском **сделай 3 тестовые заявки** и убедись, что администратор их получает.

## 4. Публикация на GitHub Pages (бесплатно)
Если уже делал для барбершопа, всё то же самое. Коротко, из папки проекта в терминале:
```bash
git init
git add .
git commit -m "Сайт стоматологии"
git branch -M main
git remote add origin https://github.com/ТВОЙ_НИК/dental-site.git
git push -u origin main
```
Перед этим создай пустой репозиторий `dental-site` на github.com (без README и .gitignore). Затем **Settings → Pages → Deploy from a branch → main / (root) → Save**. Через 1-2 минуты сайт откроется по адресу `https://ТВОЙ_НИК.github.io/dental-site/`.

Обновления: `git add .`, `git commit -m "что изменил"`, `git push`.

Важно: для клиента делай **отдельный репозиторий** и не выкладывай туда чужие данные клиники, пока они не согласованы.

Альтернативы бесплатного хостинга: Cloudflare Pages и Netlify (подключаются к тому же репозиторию, дают быструю раздачу и автоматический HTTPS).

## 5. Свой домен
1. Клинике нужен домен (например, `название.kz`). Покупается у аккредитованного регистратора .kz, обычно около года оплаты вперёд. Домен оформляй **на клинику**, а не на себя.
2. В **Settings → Pages → Custom domain** впиши домен и включи **Enforce HTTPS**.
3. У регистратора добавь DNS-записи, которые покажет GitHub (для основного домена записи A на адреса GitHub Pages, для `www` запись CNAME на `ТВОЙ_НИК.github.io`). Актуальные адреса бери из документации GitHub Pages, а не из памяти.
4. Подожди от нескольких минут до суток, пока домен заработает. Проверь, что открывается по `https://`.
5. Обнови `siteUrl`, `robots.txt` и `sitemap.xml` на новый адрес.

## 6. Поиск и карты
- **2ГИС и Google Карты:** заведи или обнови карточку клиники, добавь ссылку на сайт, часы работы, фото. Для стоматологии это даёт больше обращений, чем сам сайт.
- **Google Search Console и Яндекс Вебмастер:** добавь сайт, подтверди владение, отправь `sitemap.xml`.
- **Яндекс Метрика (по желанию):** создай счётчик, впиши номер в `CONFIG.metrikaId`. В Метрике настрой цель `booking_submit` (она уже отправляется при заявке).
- Цены, врачи и услуги рендерятся скриптом. Google это читает, но для серьёзного SEO позже лучше отдельные страницы на каждую услугу.

## 7. Проверка перед запуском
- [ ] Нет слов «заглушка», «Имя Фамилия», «00 00», `example.com` (проверь поиском по проекту).
- [ ] Номер телефона и WhatsApp ведут к реальному администратору.
- [ ] Тестовая заявка (запись и обратный звонок) дошла.
- [ ] Адрес, часы работы и подсказка про вход верны. Ссылка на 2ГИС открывает нужную точку.
- [ ] Цены совпадают с прайсом клиники.
- [ ] Лицензия, БИН и название организации в подвале верны.
- [ ] Юрист прочитал `privacy.html` и тексты.
- [ ] Сайт открыт с настоящего телефона (iPhone и Android) по мобильному интернету.
- [ ] HTTPS включён, домен открывается с `www` и без.
- [ ] Лицензию, врачей и отзывы владелец клиники одобрил письменно (хотя бы в мессенджере).

## 8. После запуска
- Раз в месяц проверяй цены и заявки.
- Если токен или пароль случайно попал в репозиторий, сразу отзови его и выпусти новый: удалить файл недостаточно, ключ остаётся в истории.
- Договорись с клиникой письменно: кто платит за домен и хостинг, кто правит цены, что входит в поддержку.

## Что я не мог проверить за тебя
Это сделано и протестировано в браузере: формы, калькулятор, фильтры, скрытие пустых блоков, отправка на сервер и запасной путь, телефон и десктоп. Но реальную отправку в WhatsApp или Telegram, DNS и домен, настоящие данные клиники и юридические требования я проверить не мог. Они остаются на тебе и на клинике.
